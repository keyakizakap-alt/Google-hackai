# デモのカレンダー（ログインなしで連携を体験）

審査員やデモの視聴者が、Google へのログインや同意画面なしで「カレンダー連携 → ライブの自動取り込み → 空き時間 → プラン作成」を体験できるようにする仕組み。
アプリ（Cloud Run の実行サービスアカウント）が、共有されたデモ専用カレンダーだけを読み取り専用で読む。鍵ファイル・パスワードは使わない。

> **デモ専用のアカウント・カレンダーを使い、架空の予定だけを入れること。** ボタンを押した人は全員同じ内容を見る。

## 1. デモ用の Google アカウントを作り、予定を入れる

アプリはタイトル・場所から「ライブらしい予定」を自動で見つける。例（日付は今日から 1〜3 か月後にする）:

| タイトル | 場所 | 時間 | 自動取り込み |
|---|---|---|---|
| IVE WORLD TOUR 京セラドーム大阪 | 京セラドーム大阪 | 18:00〜21:00 | される |
| SEVENTEEN ライブ 東京ドーム | 東京ドーム | 17:00〜20:00 | される |
| Mrs. GREEN APPLE 公演 | 日本武道館 | 18:00〜21:00 | される |
| 美容院（カット） | | 11:00〜12:00 | されない（空き時間の計算にだけ使う） |
| 仕事：定例ミーティング（毎週） | | 10:00〜11:00 | されない（同上） |
| 歯医者 | | 19:00〜20:00 | されない（同上） |

ライブ以外の予定は「埋まっている時間帯」としてだけ使われ、中身はすぐに捨てられる。
会場はアプリが知っている会場名（`src/lib/eventDetection/venues.ts`）だと、最寄り駅まで自動で入る。

## 2. Cloud Shell で設定する

```bash
cd ~/Google-hackai && git pull
export OSHIREADY_PROJECT_ID='your-project-id'
bash scripts/cloud-run-enable-demo-calendar.sh
```

スクリプトが表示するアドレス（`oshiready-runtime@…iam.gserviceaccount.com`）に、デモのカレンダーを共有する:
Google カレンダー（パソコン）→ 設定 → マイカレンダーの設定でデモのカレンダーを選ぶ →「特定のユーザーまたはグループと共有する」→ アドレスを追加し、権限を「予定の表示（すべての予定の詳細）」にする。

続けてカレンダー ID（ふつうはデモ用アカウントのメールアドレス）を入力すると、Cloud Run に `DEMO_CALENDAR_ID` が設定される。

## 3. 確認

- アプリのホーム／イベント／設定に「デモのカレンダーで試す」が出る
- 押すと数秒でライブ 3 件が登録され、空き時間のヒートマップに予定が反映される
- 「読み込めませんでした」と出る場合は、共有したアドレスと権限を確認する（反映に数分かかることがある）
- 設定画面の「デモをやめる」で元に戻る

## しくみと安全性

- 読み取り専用の権限（`calendar.events.readonly`）で、共有されたカレンダーだけを読む。予定の変更はできない
- 予定データはこれまでと同じ共通の安全チェック（`src/lib/sources/gate.ts`）を通り、保存・ログ出力はしない
- 「デモを使っている」という目印だけを Cookie に持つ（秘密の値は含まない、24 時間で失効）
- 使わなくなったら、デモのカレンダーの共有からサービスアカウントを削除し、`DEMO_CALENDAR_ID` を外す
